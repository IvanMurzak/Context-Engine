01 · Vision

One engine, every client is equal

A minimal-kernel engine where every feature is a package — builds scale from a tiny headless simulation to a full RTX-class 3D game, and 2D is first-class. A headless EditorKernel is a live derived index over your project files (the language-server model): every authored mutation is a file write, and GUI, CLI, and AI agents are equal clients over one RPC surface. What you play in the editor is what ships — the editor embeds the same RuntimeKernel the build uses.

02 · Foundation

Four load-bearing principles

Everything else in the design derives from these four. Each one forecloses a class of architecture and buys a class of capability — they are why incumbents can't follow.

1

Headless core, thin clients

All capability lives in EditorKernel; GUI, CLI, and AI are equal clients with the same public contract — file writes for mutations, one RPC surface for everything else.
⇒ CLI-completeness, automation, the single-instance bridge.

2

Simulation is authoritative; rendering is a detachable observer

State lives in the simulation; render reads a one-way snapshot and can be removed entirely.
⇒ GPU-free headless, determinism, Factorio-class optimization.

3

Minimal kernel; everything is a package

The kernel is ~6 interfaces; all features compose onto it and dead-code-eliminate out of builds that don't use them.
⇒ tiny builds, true modularity.

4

Files ARE the project

Authored state lives only in project files; EditorKernel is a restartable incremental derivation engine over them — the language-server model. The law: changes-what-git-would-commit ⇒ file write; everything else ⇒ RPC. No Save button. Git is the undo system.
⇒ AI-first authoring, git-native collaboration, crash safety, hot reload for free.

05 · The Core Loop

Anatomy of one authoring mutation

The same five steps whether the writer is the GUI, a CLI verb, or an AI editing text. This loop is hot reload, is crash recovery, is collaboration.

1

Atomic file write

GUI commits at gesture end · CLI verbs rewrite files · AI edits text directly

2

Watch + hash

Watcher hints; content-hash reconciliation marks the file dirty — hash is truth

3

Incremental derive

Only the dirty subgraph recomputes: parse → validate → compose → instantiate

4

Fan-out

Change events reach every attached client; generation counter + settled quiescence

5

Live swap

Embedded RuntimeKernel hot-reloads via handle invalidation. Builds skip it all — packed binaries

🧬

Data model

Canonical pure JSON + per-kind JSON Schema. ~1 MB / 1k-entity file granularity with binary sidecars. Dual-form refs {$ref: guid, path}. GUID + .meta.json identity. Parse-time schema migration with per-payload componentVersions. SI units + radians, by law.

🧩

Scene composition

No prefab concept — scenes instance scenes. Nested-instance overrides addressed by id-path, innermost-out precedence, provenance chains on every composed value. Flatten emits GUID-addressable streamable content units.

♻️

Concurrency & recovery

Per-file atomicity (no cross-file transactions). Daemon-per-worktree; parallel agents merge via git + the structural driver. Intent-log resume after kill -9; incarnation epochs; backpressure with load-shed to visible subgraphs.

07 · Public Contract

One self-describing surface

Built for a decade of agents: the whole capability surface is generated from one registry — so CLI ≡ RPC ≡ MCP ≡ introspection is proven by CI, not by promise (R-CLI-007…017).

📖

context describe --json

Whole-contract self-description: every verb, event, error, and capability — machine-readable. The agent corpus learns from the engine itself.

🧾

Uniform envelope

One result envelope, a versioned error-code catalog (additive-only, CI-enforced), an exit-code table, and a verb grammar with a package namespace.

🤝

Capability negotiation

Attach handshake carries {protocolMajor, capabilities[]}. v1 = hard-fail on mismatch, no silent fallback; protocolMajor=0 until the M3 freeze.

🔍

Query language

EBNF-specified operators, total ordering, unified cursor/paging, and a read-your-writes barrier (--after-generation).

📬

Events & subscriptions

Topic introspection, subscribe/ack protocol, the derived-world generation counter, derivation.settled quiescence, incarnation epochs.

🔁

Idempotency & batches

Client-supplied idempotency keys, --atomic-plan batches, transport-portable large-result handles. Multi-file verbs resume safely.

08 · Security

Trust, designed in

An engine whose primary users include autonomous agents needs a real trust model — not a warning dialog.

🔑

Cryptographic trust root

First-party release signing from the very first toolchain download: pinned publisher key, detached signatures, verify-before-use, fail closed (R-SEC-009 / L-58). TUF/Sigstore slots behind the same gate in v2.

📦

Tiered package trust

AI-installed packages default to the sandboxed constrained-ABI tier; the native tier is first-party or explicitly consented. No third-party native packages in v1 — an honest surface.

🎫

Scoped attach tokens

Per-client authorization enforced in the RPC dispatcher, not the MCP adapter. A read-scoped token cannot install a package or trigger a build. Async consent for elevation.

🧱

Isolation everywhere

Importers run subprocess-isolated; writes are path-jailed to the project; npm installs run --ignore-scripts; the intent log is HMAC-integrity-checked; CEF runs a concrete sandbox spec.

09 · Strategy

The beachhead wedge

"General 3D engine" is the destination, not the day-one claim. v1 targets three segments where the moat is decisive today — on desktop, Linux-server, and web. When scope pressure hits, wedge work outranks general-engine breadth.

PILLAR 1🧠

Headless AI-training / RL

Deterministic, GPU-free, massively parallel simulation on commodity machines. Many cheap headless instances stepped, seeded, and state-hashed from one controller. Honesty: we don't chase GPU-vectorized samples/sec — we win on agent-authored environments + orchestration.

PILLAR 2🌐

Deterministic server sim & multiplayer

The native/WASM deterministic tier — with a CI state-hash gate — plus netcode hooks, serving lockstep and state-sync server-authoritative games. Determinism is designed in, not bolted on.

PILLAR 3🎨

AI-generated 2D & simple-3D games

The agent authoring loop over first-class 2D (sprites, tilemaps, 2D physics) and baseline-3D PBR content. A complete game is buildable with zero AI usage too — the subscription is a pricing lever, not a tooling gate.

⛔ Why not MCP-on-Unity/Godot/Unreal?

  • Editors require a GPU/display for core authoring paths
  • Scene truth lives in editor memory + binary formats — a plugin mediates state it doesn't own, and races it
  • One GUI editor instance per seat — no parallel agent authoring
  • Determinism cannot be bolted on from a plugin
  • We ship the Unity/Godot/Unreal MCP plugins ourselves — proof an adapter only reaches what the host chooses to expose

✅ What Context does instead

  • Headless-complete: every authoring capability on a GPU-less, display-less host
  • An agent's file edit IS the mutation — no reconciliation, no racing
  • Daemon-per-worktree + structural merge: N agents author one game in parallel
  • Native determinism with a CI state-hash gate
  • MCP is table stakes — the moat sits below the adapter, in the architecture

2% royalty

The base is gross receipts — storefront/platform fees are not deducted — and the royalty is unconditional: no subscription of any kind affects it. The repo is public from day one under the proprietary Context Engine EULA — the un-gated Unreal mechanism. Read it, build with it, ship games with it; no one can fork it into a competing engine. CLA with copyright assignment required for contributions.

Full engine, no subscription required, zero AI usage required. A complete game is buildable with the GUI + CLI alone. The subscription buys AI usage, not the engine.

Royalty enforcement is contractual-only — no phone-home, no telemetry gate. Terms lock per engine version: the deal you adopted is the deal you keep. Deny-by-default dependency-license allowlist + SBOM from the first commit.
