# Design Review — Round 4 (2026-07-02) — data-model deep-dive · testing/CI · YAGNI/scope

> Campaign round 4 (rounds 0–3 → PRs #110–#114). **Verdict:** (A) the single-file data model is
> rigorous but nearly every gap lives at the SEAMS between files — 9 findings are M2-bytes-on-disk
> (retrofit-hell if M2 ships without them); (B) the rounds built an excellent gate LIST but no test
> SYSTEM (no self-test architecture, no determinism triage, no perf methodology, no fault-injection
> harness); (C) the requirement SUM is sized for a 30-engineer org — a v1-lean pass keeps every
> invariant/seam while deferring machinery whose subjects don't exist in v1.

## A. Data model (encode into M2 schema design — TD-decided)

1. **Nested-instance override addressing (CRITICAL)**: override entries target an **id-path**
   `{target:[instanceId,…,entityId], component, path, value}`; precedence = innermost-out, the
   outermost instancing scene wins; any level may override any deeper level (incl. re-override);
   gesture/merge/conflict paths (L-30/R-FILE-012) extend to the same id-path form. → L-35 amend.
2. **Composed write-path + provenance chain (CRITICAL)**: provenance is a CHAIN
   `[{source: schemaDefault|template|override, file, pointer, level}]` (first = winning value);
   `context set` on a composed entity writes an override in the OUTERMOST (root) instancing scene
   by default; `--edit-template` targets the defining file; `--at-instance <idPath>` targets a
   mid-level; result envelope reports the file/pointer written. → R-CLI-006 + L-35 amend (public
   contract — cannot slip past M2).
3. **Per-component-payload schema versions (CRITICAL)**: per-file header map
   `componentVersions: {"<ns>:<type>": <schemaVersion>}`; tool saves stamp current; parse-time
   migration selects per-payload migrations by stamp; `context migrate` advances. → L-32/L-37 amend.
4. **Package-migration execution contract (CRITICAL)**: migrations live in the owning package
   beside the schema, SANDBOXED tier only (TS/WASM constrained ABI; native prohibited); the
   migration set's content-hash joins the derivation cache key (amend R-FILE-010 key + R-FILE-005
   purity = "(files, engine version, registered schema+migration set)"); migrations pure,
   deterministic, CI-round-trip-tested; DOWNGRADE rule: payload version > installed schema version
   ⇒ `schema.newer_than_package` diagnostic + last-good retained, never best-effort parse;
   R-PKG-005 extends to data-version compatibility.
5. **Override migration**: a component migration receives + MUST transform both payloads AND
   override/reference paths targeting that type; unmappable paths → orphan-override diagnostics
   (carrying pre-migration path); dangling overrides are EXCLUDED from flatten (composed value =
   template value), never fail composition. → L-37/R-FILE-012 amend.
6. **Entity-ref value type**: same-file `{"$entity":"<id>"}`; into an instance subtree
   `{"$entity":[instanceId,…,entityId]}`; cross-scene-file refs to non-instanced scenes PROHIBITED
   v1 (stated); flatten remaps to composed runtime ids; dangling entity-ref joins validate;
   typed entity refs via the schema vocabulary (item 9). → L-34 sibling entry in M2 schema.
7. **Composed/runtime identity**: composed entity id = deterministic id-path
   `[rootScene, instanceId…, entityId]` (or stable hash), stable across re-derivation/upgrade;
   migrations MUST NOT alter entity/instance ids or GUIDs (restructuring emits a deterministic id
   map); saves (R-DATA-005), net-ids (R-NET-001), and query results share this one identity. →
   L-37 + flatten/pack design (M2).
8. **Id allocation vs merge**: intra-file ids are collision-resistant random (≥64-bit,
   file-scoped); merge rule: same id + differing fields = same entity (field-merge); same id both
   ADDED vs base = structural conflict; post-merge validate gains duplicate-intra-file-id
   diagnostic + a re-key verb that rewrites in-file refs; meta same-path/two-GUID conflicts =
   whole-asset ours/theirs, never field-merged. → L-33/R-FILE-012 amend.
9. **Schema vocabulary (CRITICAL for M2 kinds)**: `x-ctx-type` (quat, color+space, curve,
   gradient, flags), `x-ctx-storage` (numeric width/layout — feeds R-LANG-010 layout derivation),
   `x-ctx-ref` (required target kind, enforced by the derivation validator via meta lookup),
   pinned tagged-union convention `{"type":"<ns>:<shape>",…}` for polymorphic fields, and the
   **units law: SI + radians everywhere**, per-field `x-ctx-units` surfaced in introspection
   (R-CLI-005/013). → L-32 amend + new requirement.
10. **Binary sidecars**: authored files with magic + format-version header; per-kind versioning +
    migration extends L-37; referenced as `{"$sidecar":"<relpath>", "hash":"<raw-byte hash>"}`
    (raw hash ≡ canonical hash for binaries — state in R-FILE-001); move/rename treats sidecars as
    owned satellites (like meta); R-FILE-012: binaries NEVER merged — whole-file ours/theirs in
    the conflict envelope; overrides may replace the sidecar REFERENCE, never patch bytes; write
    order: sidecar first, then referencing JSON. Needed M2 day one (tilemaps). → L-33 amend.
11. **Scene-level state**: singleton components on a well-known scene-root entity (overrides/
    queries/provenance/merge/migration apply for free); when instanced as a sub-scene, root
    scene-settings components are INERT by default; a component type may declare `composable` to
    opt in; nav/lighting BAKES are derived artifacts (L-28 cache), not authored. → L-35 amend.
12. **Runtime save migration**: save format records the per-component schemaVersion map (item 3);
    RuntimeKernel ships a MINIMAL save-migration runner; builds embed the sandboxed-tier migration
    functions for exactly the compiled component set; declare save-back-compat scope (N versions).
    → R-DATA-005 amend (M2 groundwork).
13. Override staleness: override entries record `base` (template value at creation);
    `context query --overrides diverged` lists divergence; advisory only. [MINOR]
14. Redundant-override GC: validate diagnostic + `--fix` prune; `context set`/GUI prunes at write
    when value == composed base. [MINOR]
15. Direct instancing-cycle diagnostic (validate error at the edge closing the cycle), independent
    of the depth cap. [MINOR]
16. Meta schema reserves `platforms: {"<profile>": {…}}` per-platform import-setting overrides in
    M2. [MINOR]

## B. Testing & CI (TD-decided — new R-QA-008…012, R-PKG-006 + amendments)

- **R-QA-008 (MUST) — engine test architecture**: unit tests per kernel component/package;
  property+integration suites for the file-sync layer (promotes the §7 risk note to requirement);
  golden-file suites for canonical serialization, migration, structural merge; protocol
  conformance suite generated from the R-CLI-009 registry; each milestone exit includes its suite
  green, not only its demo. Minimal v1: kernel + file-sync + canonical serializer at M1.
- **R-QA-005/L-54 amend — determinism TRIAGE**: hierarchical state hash (per-tick, per-system,
  per-archetype sub-hashes; trace mode); on divergence auto-triage: replay-bisect to first
  divergent tick, diff first divergent system; `context determinism diff` reports
  (tick, system, entity, componentField); matrix names its platforms (min Linux-x64, Win-x64,
  macOS-ARM64) per the fleet manifest.
- **R-QA-009 (MUST) — perf-gate methodology**: named dedicated perf-isolated runner classes
  (R-QA-007 proxy device defined by name); median of N≥5 with dispersion recorded; fail only on
  breach confirmed vs rolling baseline within a documented variance band; results archived as
  time series. Minimal v1: one bare-metal Linux perf box, median-of-5, ±10%.
- **R-QA-010 (MUST, M1) — daemon fault-injection harness**: file-sync built on injectable seams
  (virtual FS, watcher, clock); deterministic-simulation harness: crash points between every
  durable step of every multi-file verb (assert resume-or-diagnostic per R-FILE-004);
  watcher loss/dup/reorder (assert convergence per R-FILE-002); slow-client overflow (assert
  gap-marker+resnapshot per R-BRIDGE-008); failing seeds minimized + committed. Seams are M1
  architecture — cannot retrofit.
- **R-QA-011 (MUST) — test corpora as versioned deliverables**: migration fixtures per schema
  bump (pre + golden post); 3-way merge corpus per documented conflict class; malformed-file
  corpus (one per error-catalog code); importer fuzz seed corpora committed+minimized;
  composition edge-case scenes.
- **R-QA-012 (MUST) — CI fleet manifest**: versioned manifest maps every CI-enforced requirement →
  runner class (OS/hardware/GPU/device-proxy/isolation) + build flavor; provisioning = named
  milestone de-risk items; unprovisioned rows marked "gate advisory until provisioned".
- **R-EDIT-001/§14c amend — editor testing**: editor panels built over a headless-instantiable
  UI-logic tree (R-UI-006 extended to editor UI) so palette/undo/Problems/inspector logic is
  CI-assertable without CEF; per-OS CEF boot smoke gates M5; R-A11Y-001 enforced by automated a11y
  scan + keyboard-only nav test per new panel; R-HUX-011 measured from instrumented timestamps.
- **M4 exit amend — visual equivalence method**: golden-scene corpus rendered offscreen per
  backend; named perceptual metric (SSIM-class) + per-scene tolerance on the GPU runner class;
  rebaselines reviewed. Minimal v1: Linux-Vulkan + one browser blocking, others advisory.
- **R-QA-005 amend — replay artifact**: versioned schema'd kind (input stream + seed + tick count
  + engine/protocol versions + content-hash manifest + expected per-tick hash trace in
  deterministic mode); replay verifies manifest, reports first-divergence tick; non-deterministic
  replay labeled best-effort. Pin before M3.
- **R-PKG-006 (SHOULD v1 / MUST pre-marketplace) — package conformance kit**: `context package
  verify` (contract, declared-access honesty under instrumented build, schema validation,
  namespace+compat, determinism attestation harness for sim-tier); reference CI template.
- **R-FILE-001 amend**: cross-implementation canonical test-vector corpus (float edges/-0/
  subnormals, NFC, ordering), byte-exact across C++/TS writers; serialize∘parse idempotence +
  re-canonicalization fixpoint property tests.
- **R-SEC-006 amend — fuzzing model**: continuous out-of-band fuzzing (OSS-Fuzz-style) with
  committed corpora; per-PR = corpus regression only; targets: importers, authored-JSON
  parse/canonicalize, merge-file, RPC frame decoder; crashes auto-file minimized repros.
- **CI tiering table (plan)**: blocking per-PR = sanitizers · determinism hash (wedge platforms) ·
  importer double-run · CLI≡RPC≡MCP + catalog-additive · license/SBOM/CLA · smoke-run (wedge
  targets) · 10k-file bench variant; nightly/trend = 100k bench + contention + dense-ref ·
  build-time · TS frame · min-spec · backpressure · fuzz · session p99. Red-X policy per gate
  (blocking / advisory / quarantine-with-issue).
