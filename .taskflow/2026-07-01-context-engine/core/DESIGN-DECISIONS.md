### File-authoritative EditorKernel & the client bridge (L-19…L-31)

| # | Decision | Rationale | Normative home |
|---|---|---|---|
| L-19 | **File-authoritative EditorKernel (LSP model)**: project files are the single source of truth for authored state; EditorKernel is a restartable incremental derivation engine over them; CLI mutation verbs are file rewriters. The law: *if it changes what would be committed to version control, it happens as a file write; everything else (queries, play/pause, build, screenshots) is an RPC.* Scope: EditorKernel only — see L-24 for RuntimeKernel. | AI/CLI-first authoring; git-native collaboration; crash-safe; no dual-truth reconciliation. | R-ARCH-002 |
| L-20 | **Authored vs session state split**: authored state exists only in files; session state (selection, camera, in-flight gestures, play-mode sim) lives in EditorKernel memory (gitignored `.editor/session.json`); the GUI commits at gesture end — **no Save button**. | 60 Hz manipulations can't hit disk; an honest truth boundary; GUI and AI behave identically. | R-FILE-006 |
| L-21 | **Git is the undo system** [owner-ruled 2026-07-01]: the engine ships no undo/redo subsystem; history, checkpoints, and rollback are git commits/branches/worktrees; new Projects are git repos by default; Editor clients may add thin git sugar (GUI *session* undo over the file-write journal is R-HUX-001, a client feature). | A parallel undo machine over file-authoritative state duplicates what git does better; AI/CLI workflows live in git anyway. | R-FILE-007 (R-DATA-003 removed) |
| L-22 | **One incremental derivation graph**: parse → validate → compose → instantiate, content-hash memoized, dirty-subgraph recompute; it unifies the asset-import cache, scene composition, diagnostics, and hot reload. **The watcher is a hint; hashes are the truth** (debounced rescan reconciliation). | Scales to 10k+ files; one machinery instead of four; survives dropped FS events and bulk git ops. | R-FILE-002/005 |
| L-23 | **EditorKernel is an embeddable library**; the daemon is a long-lived shared instance of it; the CLI attaches when a daemon is alive, else operates in-process on the files with identical semantics. Attach requires a version handshake — a mismatch fails with an explicit machine-readable error, never silent degradation or a second daemon. | Offline-capable CLI; the daemon is an optimization, never a gatekeeper; mismatched versions almost certainly disagree on API. | R-FILE-008, R-ARCH-005, R-BRIDGE-006 |
| L-24 | **RuntimeKernel never parses authored files** [owner-ruled 2026-07-01]: it consumes only derivation-graph output through one loading seam — fed live in-memory in the editor (hot reload = re-derive + handle invalidation), baked into packed binaries for shipped games. No watcher, no text parsing, no derivation code in a Game Build. | RuntimeKernel ships inside builds and must stay minimal/fast; preserves editor==build fidelity (L-2/L-13) with one data format, two feeds. | R-FILE-009 |
| L-25 | **Per-file atomicity is the atomicity unit** — no cross-file transaction machinery; multi-file operations apply per-file-atomically in dependency-safe order, and mid-states resolve via eventual validity + diagnostics; durable multi-file checkpoints are git commits. | Cross-file transactions would be version-control creep inside the engine; eventual validity already absorbs mid-states. | R-FILE-003/004 |
| L-26 | **Daemon-per-worktree**: each git worktree is its own Project instance with its own EditorKernel daemon (exclusion enforced by a byte-range lock on `.editor/lock`; the canonical path is a discovery hint only); parallel worktrees = parallel humans/AI agents on the same game, converging via git merges. Engine/package upgrades are **worktree-atomic** — run `context migrate` + commit on a shared base before mixed-version work resumes — and a merge input stamped newer than the running engine/package set is a whole-file ours/theirs conflict class, never a parse error. | Cheap, contention-free parallelism aligned with git-as-history (L-21); worktree-atomic upgrades keep parallel worktrees from durably diverging in schema generation. | R-BRIDGE-001; mixed-version rules: R-FILE-012, R-PKG-005 |
| L-27 | **Git is a convention, not a runtime dependency**: EditorKernel never invokes git (no shell-out, no embedded git library in core); it only observes files changing; new-Project templates initialize a repo; git sugar lives in Editor clients only. Without a repo everything works — there is simply no history. | The reconcile pipeline (L-22) already handles any external change source; keeps the core dependency-free. | R-FILE-007 |
| L-28 | **Hybrid derivation cache** — a machine-level, per-user, content-addressed shared cache; per-project override for CI/hermetic builds; a team-level remote cache is a natural later extension. **Normative home: R-FILE-010** (with R-BUILD-006 for the cache-exempt LTO-link/per-build costs) — the fine-grained keys (including the migration-set hash), write-once/self-verifying entries, LRU/pinning/`context cache` CLI, code-artifact trust rules, and the v1 one-trust-domain simplification all live there. | Fresh worktrees derive near-instantly — the multiplier that makes L-26 parallelism real; dedup across projects only when reuse is provably correct; derivation purity (R-FILE-005) makes sharing sound. | **Pointer row** → R-FILE-010 (+ R-BUILD-006) |
| L-29 | **JSON-RPC 2.0 over the local socket/named pipe** is the wire format for the non-file RPC surface (queries, session actions, derived outputs, event stream, attach handshake); oversized responses return a temp-file/resource handle; EditorKernel ships a **built-in MCP adapter** as a first-class client door (tool schemas generated from the versioned RPC schema). The endpoint is local-only by default — user-only pipe permissions + a per-instance auth token; remote exposure is a separate, explicitly-gated feature. | Zero-dependency clients; human-debuggable; LSP-proven at exactly this workload; MCP is itself JSON-RPC 2.0, so the AI door is nearly free. | R-BRIDGE-003/007 |
| L-30 | **Gesture-conflict policy = rebase-or-drop-loudly**: at gesture commit the Editor re-reads current file state; if the gesture's field paths are untouched by the external change it rebases onto the new state; if they collide — at field-path granularity, addressed by (entityId, componentType, intra-component path) over stable ids, never raw array indices — the gesture is dropped with a visible notification + diagnostic + event, never a silent overwrite in either direction. | Respects files-as-truth while keeping the GUI alive; disjoint human+AI co-edits cost nothing; mirrors git-rebase semantics. | R-FILE-006, R-COLLAB-001; merge machinery: R-FILE-012 |
| L-31 | **Event stream contract**: topic subscriptions (`files`, `derivation`, `diagnostics`, `session`, `clients`, `log`; optional path scoping); sequenced delivery with snapshot-on-subscribe + ring-buffer catch-up; bulk changes coalesce; slow subscribers get bounded queues + explicit gap markers; events are post-derivation **facts**, never raw FS noise. The central concurrency primitive: a monotonic **derived-world generation** stamped on every query/snapshot/batch, a **`derivation.settled{generation}`** quiescence event, a `stability` field on diagnostics, an **incarnation epoch** forcing a fresh snapshot on daemon restart, and a read-your-writes barrier (`--after-hash`/`--after-generation`). | Intermittent AI clients reconnect correctly by construction (snapshot-then-delta); "did my write take effect and has the world quiesced?" is machine-answerable. | R-BRIDGE-008 (retention: R-CLI-015; schema: R-CLI-004) |

### Data & content model (L-32…L-37)

| # | Decision | Rationale | Normative home |
|---|---|---|---|
| L-32 | **Canonical JSON is the authored format**: every authored file kind is pure JSON (UTF-8, LF), canonically serialized (stable key order, fixed indentation, stable array ordering), carrying `$schema` + `version` + a per-component **`componentVersions`** map, with a published, versioned JSON Schema per kind sharing the engine **schema vocabulary + units law** (`x-ctx-type`/`x-ctx-storage`/`x-ctx-ref`, the pinned tagged-union convention, SI + radians with per-field `x-ctx-units`). **No comments** — human/AI annotations live in schema-blessed `notes` fields; TS/shader sources are the authored-**text** carve-out with toolchain-defined formatting and compile/typecheck diagnostics per R-FILE-003. **Confirmed by measurement** [spike-ratified 2026-07-02, owner]: 100k-file fresh attach (parse+canonicalize+hash) = 1.74 s saturated / 11.32 s single-core — 14× / 2.2× inside the 5× miss line (`spikes/parse-bench/FINDINGS.md`). | LLMs are most reliable with JSON; schema validation powers the one-loop self-correction; one mental model across files, CLI I/O, and RPC. | R-FILE-001, R-DATA-001/006 |
| L-33 | **File-granularity rules**: one scene per file; large worlds compose many small instanced scenes; a soft per-file ceiling (~1 MB / ~1k entities) with split-nudging diagnostics; heavy numeric payloads live in versioned **binary sidecars** (`{"$sidecar": "<relpath>", "hash": "<raw-byte hash>"}`, owned satellites on move/rename, never content-merged — whole-file ours/theirs — written before the referencing JSON) rather than inline base64. Entities/components carry **stable intra-file ids** — collision-resistant random (≥ 64-bit, file-scoped), never sequential — and child lists serialize as id-keyed ordered collections, landing in the M2 schema. **Confirmed + encoding pinned** [spike-ratified 2026-07-02, owner]: the ~1 MB ceiling and sidecar rules are validated by the same parse-bench measurement (a ceiling scene costs ~3.7 ms single-core), and id-keyed child collections are realized as **arrays of objects carrying a stable `id` member** — the map-keyed form is forbidden (it cannot survive canonical key-sorting; normative wording in R-FILE-001). | Authored files must fit AI context windows and diff locally (the AI-first constraint); keeps JSON semantic, reviewable, and fast to parse at 100k-file scale; random ids make parallel-worktree merges collide only on genuinely-shared entities. | R-FILE-001/011/012 |
| L-34 | **Dual-form references**: every cross-file reference serializes as `{"$ref": "<guid>", "path": "<readable hint>"}` — the GUID is authoritative, the path a hint auto-healed on tool save; path-only refs are accepted and resolved by `context validate --fix` and tool saves. Cross-**entity** refs have a defined sibling: same-file `{"$entity": "<id>"}` or an id-path into an instanced subtree; cross-scene-file refs to non-instanced scenes are **prohibited in v1**; target-kind typing comes from `x-ctx-ref`. | Stable across renames yet human/AI-readable; agents can author references without knowing GUIDs. | R-ASSET-002, R-DATA-006 |
| L-35 | **Scene composition model**: a scene instances other scenes with per-instance, per-field override entries — **id-path addressed** (`[instanceId, …, entityId]`, innermost-out precedence, the outermost instancing scene wins) — plus explicit structural overrides; composition **flattens in the derivation graph at zero runtime cost**, and the flatten output is co-designed with the chunked pack format so flatten boundaries are the runtime content-unit boundaries; there is no separate prefab concept. The composed **write path is public contract**: `context set` on a composed entity writes an override in the outermost instancing scene by default (`--edit-template`/`--at-instance` retarget; provenance is a chain — R-CLI-006); scene-level state is singleton components on a well-known scene-root entity (inert by default when instanced as a sub-scene, `composable` opt-in; bakes are derived artifacts, never authored); override hygiene (divergence listing, redundant-override pruning, instancing-cycle diagnostics) is advisory tooling. | One uniform concept; overrides are visible, greppable lines — not opaque blobs; editing a template updates all non-overriding instances (Unity-prefab power via plain file semantics). | R-DATA-002, R-ASSET-005, R-CLI-006, R-FILE-012 |
| L-36 | **Asset identity = GUID + sidecar meta**: every asset gets an immutable GUID in `<asset>.meta.json` alongside its import settings; references use the GUID (L-34); CLI move/rename verbs keep meta in sync and the watcher heals raw moves by GUID match; the M2 meta schema reserves a `platforms` block for per-platform import-setting overrides. | Identity survives rename/move at 100k-file scale; per-asset settings live next to the asset; the proven model. | R-ASSET-002 (import-cache half: R-FILE-010) |
| L-37 | **Schema evolution**: versioning is **per-component-payload** (the `componentVersions` stamps); the engine reads old versions by migrating **at parse time** without touching disk; tool saves canonicalize the whole file they write and stamp current schema versions, while explicit `context migrate` is the bulk path for otherwise-untouched files; the compiled runtime format carries no compatibility burden (regenerated cache). Package-shipped migrations run in the **sandboxed tier only** under a per-invocation time/instruction budget, are pure/deterministic/CI-round-trip-tested, transform override/reference **paths** as well as payloads (unmappable paths become orphan-override diagnostics excluded from flatten), and must never alter entity/instance ids or GUIDs — composed identity (the deterministic id-path) survives re-derivation and upgrade, shared by saves, net ids, and query results. Payloads stamped newer than the installed schemas yield `schema.newer_than_package` / `schema.newer_than_engine` diagnostics with last-good retained — never a best-effort parse. | Old projects always open; truth on disk never mutates silently; migrations are testable, bounded pure functions — a pathological migration cannot hang derivation. | R-DATA-004, R-PKG-005; cache keying: R-FILE-005/010; merge: R-FILE-012 |

### Execution & runtime (L-38…L-41)

| # | Decision | Rationale | Normative home |
|---|---|---|---|
| L-38 | **Declared R/W access sets + auto-parallel scheduler**: systems declare component read/write sets; the scheduler parallelizes non-conflicting native/WASM/engine systems plus chunk-level parallelism in hot loops; TSan/ASan/UBSan-gated CI from day one. TS systems occupy a **single scheduler lane** (one JS VM = one thread) and are excluded from DAG construction; TS enforcement is at the view seam (declared-view handout in release, debug-mode Proxies that throw on undeclared access); the schedule DAG is computed once per composition change and **cached, never rebuilt per frame**, with small-system batching. Isolate-pool parallel TS is a post-v1 investigation against the chosen backend (V8 — L-61). | Safe auto-parallelism that scales to third-party packages; the declarations double as machine-readable metadata for AI reasoning and tracing (R-OBS-004); the DAG is a compile-once artifact of composition. | R-SIM-006, R-LANG-009/011 |
| L-39 | **Extract into a render world**: an extract step copies render-relevant state into a separate, double-buffered render world; the render thread reads only that snapshot; headless = the extract step never runs. Extract queries the shared broad-phase spatial index (R-SIM-007), so its cost is bounded by the visible set rather than an O(N) world scan; the **sim→render timing contract** — tick-rate policy, render-side interpolation/extrapolation between fixed ticks, and the high-refresh presentation rule (144 Hz display on a 60 Hz tick = interpolated frames, never re-simulation) — is designed in M1 under R-SIM-002. | Copy cost scales with the visible set, not world size; render never blocks or mutates sim; double-buffering gives interpolation its two endpoints. | R-REND-003, R-SIM-002/007 |
| L-40 | **TS-tier execution = a JS VM per platform**: JIT where legal, the browser's own engine on the web target; **TS does not compile to WASM in v1** — WASM is the format for the native/perf tier and sandboxed third-party modules, and R-LANG-004's "compiles to the per-platform format" means bundle/transpile to JS for the TS tier. The iOS leg — the interpreter-where-banned configuration, the second embedded VM backend, and the bytecode precompile — is **v2 with iOS** [owner-ruled 2026-07-02]; v1 ships one embedded backend (V8 — L-61) with the multi-backend seam kept. | Arbitrary TS + npm deps → WASM is research-grade today; this is the honest per-platform story. | R-LANG-004/005, R-BUILD-001 |
| L-41 | **Fifth M0 spike — RESOLVED: the per-platform CEF compositing tree** [spike-ratified 2026-07-02, owner]. Windows = accelerated OSR **primary** (measured: 2.5 µs/frame composite p50) with the software-OSR branch **compiled-in** (measured ~4× cost — genuinely safe); macOS = accelerated via raw IOSurface with **CEF-internal pacing only** — never design against `SendExternalBeginFrame` (broken upstream, cef#4033); Linux = **software-OSR is the shipped default**, accelerated only behind a Mesa/X11-ozone capability gate (forced software on NVIDIA proprietary). Branch (1) "windowed CEF + viewport hole" is **rejected** (kills UI-over-viewport overlays; Wayland-hostile) and branch (3) inverse composition stays an unexercised last resort; the CEF ship payload is measured ≈ 389 MB (the L-15 weight tax, now a number) and CEF M138+ sandbox requires the `bootstrap.exe` launch model (M5 packaging note, ROADMAP.md). | The editor's riskiest integration seam — proven before M1 commits; software-OSR shares ~95% of the accelerated integration, so the fallback is one flag, not a second implementation. | R-UI-007; ROADMAP.md (M0 spikes, M5); evidence: `spikes/cef-compositing/FINDINGS.md` |

### Trust, collaboration, verification & platforms (L-49…L-54)

| # | Decision | Rationale | Normative home |
|---|---|---|---|
| L-49 | **Tiered package trust**: the **WASM tier is the genuinely-sandboxed tier** (no ambient capabilities by construction); in v1 **all TS runs in one shared trust domain** behind a constrained host ABI (no ambient `fs`/`net`/`process`/native addons — only engine-injected, capability-gated bindings; per-package TS isolates are post-v1); native C++ packages are an explicitly-trusted tier — signed/reviewed with a loud consent gate at install, since native code cannot be honestly sandboxed. Capability declarations are enforced in the sandboxed tier and surfaced-and-advisory for native; **AI-installed packages default to the sandbox tier**; the in-process TS tier is not crash-isolated in v1 — WASM/subprocess tiers are the containment story. | Supply-chain safety with an honest boundary; agents can never silently pull native code into the process. | R-SEC-001/002/004 |
| L-50 | **Multi-client concurrency = file authority + serialization**: attached clients' writes serialize through the daemon write queue; detached writers converge via watch–hash–reconcile; CAS via `--if-match`; coarse-grained parallelism is git worktrees (L-26); no bespoke concurrency machine in v1, CRDT co-editing a post-v1 aspiration. Stated honestly: two concurrent **raw** writes to the same file are **last-writer-wins at the byte level** — L-30 field-path rebase is gesture-only, and cross-agent parallelism is worktree-per-agent + git merge with the R-FILE-012 structural merge driver (auto-installed by `context new`); agents SHOULD mutate shared files through `context` verbs (which CAS), and the daemon emits a concurrent-write/lost-update-risk event wherever detectable. | The Topic-1 architecture already provides the guarantees R-COLLAB-* needs; the honest guarantee is CAS + worktrees + structural merge, not byte-level auto-merge. | R-COLLAB-001/002, R-FILE-004/012 |

### 1c. Material / shader system — WGSL half RESOLVED at M4 (= Tint); graph-frontend detail open (post-v1)

| Option | Pros | Cons |
|---|---|---|
| Hand-written + cross-compile (Slang→SPIRV-Cross) | Full control; AAA-standard; powerful | Variant mgmt on you; not artist-friendly; own the transpiler |
| Node-based material graph | Artist-friendly; engine controls variants; portable | Large subsystem; graph→optimal shader hard; need raw escape hatch |
| Fixed über/PBR standard | Simplest; consistent | No custom effects; dead-end |
| Shader IR (→SPIR-V→backends) | Unifies backends incl. web; future-proof | Toolchain complexity; SPIR-V→WGSL maturing |

**Lean:** material-graph frontend → shared IR/cross-compiler backend, with a raw-code escape hatch.

**What is open / what M4 must provide:** the authoring-model detail (graph frontend shape, the
raw escape hatch, variant management) resolves at M4. **M0 spike result** [spike-ratified
2026-07-02, owner]: the same shader through **Naga (native) and Tint (Chrome) rendered
byte-identical images** on the spike harness — baseline-divergence risk is low, and the WGSL
**tool choice stays the M4 deliverable**, measured on the engine's real shader corpus with the
spike harness as the fixture (R-REND-005). The cross-compile chain itself is already normative —
glslang/DXC → SPIR-V → SPIRV-Cross, with shader compilation running as cached derivation-graph
nodes (R-REND-005). Decision criteria: toolchain maturity on the sole web path post-L-56 (flagged
risk), variant-explosion control, and the graph→optimal-shader quality bar against hand-written
HLSL/Slang.

**M4 resolution (2026-07-09; engine repo `docs/wgsl-tool-decision.md`):** the SPIR-V→WGSL tool
choice is **Tint** (from Dawn, SHA-pinned), measured on the engine's real 36-module shader corpus
exactly as prescribed above: Tint translated **36/36** modules byte-deterministically with output
valid under both downstream consumers; naga translated only **20/36** (its two failure classes —
combined image samplers and matrix vertex attributes — persist in the newest naga, so not a
stale-pin artifact). naga is **retained as the second validator**: the emitted WGSL stays
permanently cross-validated under the pinned naga in CI. What M4 actually shipped for the
authoring model: the material **IR** (`ShaderIr` + the typed material contract + deterministic
variant enumeration, canonical text form) behind the `IShaderCompiler` seam, with the
glslang→SPIR-V→SPIRV-Cross(+Tint) chain running as cached derivation-graph nodes
(`src/render/material/`, `src/render/shadercc/`, `ShaderCompileNode`). The **node-graph authoring
frontend** (graph shape, raw escape hatch UX, variant-management surface) remains the open half —
post-v1.
