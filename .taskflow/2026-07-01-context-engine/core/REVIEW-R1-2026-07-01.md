# Design Review — Round 1 (2026-07-01) — perf/scale · concurrency · human-DX

> Campaign round 1 (round 0 = the 4-lens review → PR #110). Three fresh lenses on the
> post-remediation docs. TD-verified; findings the reviewers were told were already covered
> (view lifetime, one-VM-one-thread, hashing, cache keys, importer determinism, L-30/L-50/CAS
> basics) are excluded. **Verdict:** architecture still sound; the gaps are (a) a missing
> concurrency primitive (generation + quiescence), (b) an over-claim about raw-write conflict
> resolution, (c) missing runtime perf subsystems (spatial index, GC budget, TS frame budget),
> and (d) a systematically under-specified human presentation layer.

## Autonomous decisions (TD, under owner delegation) — to encode this round

### New primitive (closes the most surface)
- **Derived-world generation counter + `settled` quiescence event.** Every query/snapshot returns
  its generation; a `derivation.settled{generation}` event fires only when no dirty subgraph / no
  in-flight async import remains; snapshots are internally consistent to one generation; diagnostics
  carry a `stability` field (`provisional` until settled, then `stable`); `context validate` reports
  against the last stable generation. Read-your-writes: mutation verbs return the resulting input
  content-hash; queries accept `--after-hash H` / `--after-generation G` (bounded block); composed
  `set | query` pipes implicitly barrier. → amends R-BRIDGE-008, R-CLI-006, R-FILE-003, R-FILE-012.

### Concurrency correctness
- **Correct the L-50 over-claim (CRITICAL).** State honestly: concurrent same-file *raw* writes are
  last-writer-wins at the byte level; L-30 field-path rebase is gesture-only; cross-agent
  parallelism is worktree-per-agent (L-26) + git merge. Mitigations: **R-FILE-012 → MUST** and its
  merge driver auto-installed by `context new`; agents SHOULD mutate shared files through `context`
  verbs (which CAS) not raw bytes; the daemon emits a concurrent-write / lost-update-risk event
  where detectable (a tracked file changed outside the queue under an in-flight op).
- **Crash-recovery intent log (R-FILE amendment).** A bounded `.editor/` intent log records
  (opId, planned writes, target hashes) fsync'd before the first write, cleared after the last; on
  restart, resume (verbs MUST be idempotent + re-runnable under partial apply — promoted from the
  4 heal-writes to all multi-file verbs) or emit a diagnostic naming the incomplete op. Explicitly
  NOT a transaction/undo system (L-25 stands); write-ack occurs only after durable rename.
- **Event stream incarnation epoch (R-BRIDGE-008).** `seq` = one global monotonic counter within a
  daemon incarnation; every snapshot/event batch stamped with `incarnationId`; client forces a
  fresh snapshot on any `incarnationId` change; `seq` assigned at post-derivation emission, totally
  ordered across topics.
- **Lock/attach atomicity (R-BRIDGE-001 / R-ARCH-005).** Exclusive `.editor/lock` acquired
  atomically as the first action of any write-capable instantiation; try-lock-failure *is* the
  "instance live → attach" signal (single gate, no separate liveness check); in-process mode either
  publishes a minimal attach endpoint for its lifetime or holds a shared lock for read-only and
  escalates per-write — so it is never a gatekeeper (honors R-FILE-008).
- **Watcher change-detection (R-FILE-002).** Re-hash any *hinted* path unconditionally (mtime/size
  gate applies only to the cold full scan); add a low-frequency background full re-hash crawl (or
  fsevents-since-token replay) as the dropped-event safety net; mtime granularity documented as
  untrusted for content equality. Expected-writes entries expire on a short TTL / one debounce cycle.
- **Determinism as a whole-build property (L-54 / R-SIM-005).** Strict-FP flags engine-wide on the
  sim path; FMA/contraction pinned; a single shipped deterministic transcendental math lib (no
  platform libm on the sim path); every sim-tier module (engine, native gameplay, third-party WASM)
  MUST carry a `deterministic:true` build attestation or the deterministic build fails; CI gate
  exercises transcendentals + a representative third-party WASM system + physics; per-project
  conformance harness hashes the game's own systems.

### Runtime performance subsystems
- **R-SIM-007 (MUST) — spatial acceleration structure.** Incrementally-updated broad-phase index
  over transform-bearing entities, shared by render culling (makes L-39 "scales with visible set"
  true), spatial queries (R-CLI-006 radius/AABB), and streaming (R-ASSET-003); extract + spatial
  queries are O(result + log N), not O(N); resolves the L-39-vs-R-KERNEL-001 and
  R-CLI-006-vs-R-BRIDGE-008-5ms contradictions. (R-KERNEL-001 stays minimal: the index is a
  standard package the render/query paths depend on, not kernel core — state this explicitly.)
- **R-SIM-008 (MUST) — JS-tier GC discipline.** Per-frame GC-pause target relative to the timestep;
  engine-provided pooled/no-alloc math + query APIs for hot systems; VM configured
  incremental/generational with a scheduled inter-tick GC window; profiler GC-pause channel
  (extend L-47); cheap-GC is a §2d VM scoring criterion.
- **R-LANG-012 (MUST) — TS-tier frame budget.** Published entities×systems×Hz floor sustained in
  interpreter mode on the reference min-spec, CI-enforced; batched view handout (one view-set per
  archetype, reused across systems within a tick) + a per-frame ArrayBuffer create/detach cap;
  explicit statement that TS gameplay throughput is single-core-bound and does not scale with cores.
- **R-QA-007 (MUST) — minimum-spec floor.** Per-platform reference min-spec device + committed
  target frame-rate, CI-benchmarked; resolves R-REND-002 "graceful fallback" now that L-56 removed
  the sub-WebGPU tier (either commit a constrained path for sub-WebGPU MUST-target devices or scope
  them out of R-BUILD-001 honestly).
- **R-BUILD-006 (MUST) — build-time budget + benchmark.** Cold/incremental/clean-CI targets
  enforced by a CI build-time benchmark; hermetic CI may seed a read-only warm artifact cache
  (trusted remote cache) so cold-CI is not the default; WASM-AOT + 6-platform transcode budgeted
  separately (per-build, not cached-once) — corrects the "one build per machine ever" over-claim.
- **R-FILE-013 (MUST) — derivation-side backpressure.** Coalesce the whole dirty set into batched
  passes; publish a bounded-lag / queue-depth signal on the event stream so cooperative agents
  self-throttle; load-shed policy (prioritize queried/visible subgraphs, defer the rest); a
  documented max dirty-set latency under sustained external write load, benchmarked.
- **R-FILE-010 amendment — cache pressure.** Default cap auto-sized to observed working set ×
  active-worktree count; automatic gc under disk/size pressure; pin each worktree's active derived
  set; `cache stats` hit-rate metric; a multi-worktree contention scenario in the R-FILE-011 CI
  benchmark (so "warm attach ≤5s" is validated under contention, not in isolation).
- **R-FILE-011(a) amendment** — cold/fresh-worktree attach is bounded by *parse+canonicalize+hash*
  throughput (canonical-content hash requires parsing), not raw-byte hashing; benchmark that path.
- **R-SIM-006 / L-38 amendment** — schedule DAG derived once from the static access sets and cached
  (invalidated only on package-composition change, not per frame); small-system batching policy;
  single-lane TS systems excluded from DAG construction.
- **L-35 / R-ASSET amendment** — flattening MUST emit GUID-addressable, independently
  loadable/unloadable content-unit boundaries; co-design flatten output + chunk pack format in M2
  (not M8); **R-ASSET-003 + R-ASSET-005 → MUST for memory-constrained targets** (Android/iOS/Web).
- **R-FILE-011(e) amendment** — enumerate + bound the resident set (raw+canonical hashes, dep-edges,
  GUID index, schemas); state edges are O(refs) which may exceed O(files); M2 invariant caps
  composition nesting depth + a fan-in diagnostic; dense-reference synthetic in the CI benchmark.

### Human presentation layer (new section §14c "Human editor experience", R-HUX-*)
Systematically under-specified vs the AI surface; the machinery exists, only the presentation is
missing. Encode:
- **R-HUX-001 (MUST)** GUI session undo/redo over the file-write journal (Ctrl+Z/Y, gesture-batch
  auto-checkpoint), replayed through the same write path (queue + CAS + L-30 rebase-or-drop) so undo
  can never clobber a concurrent writer — independent of git knowledge.
- **R-HUX-002 (MUST)** git-optional human abstraction: visual checkpoint timeline, named restore
  points, background auto-commit, in non-git vocabulary, built on the permitted client git sugar
  (engine core stays git-free per L-27).
- **R-HUX-003 (MUST)** GUI launcher / project manager: create-from-template, open-recent,
  engine-version pick (R-VER-004) — the default human entry path. (Promote R-QA-006 templates → SHOULD,
  split human-onboarding samples from the agent corpus.)
- **R-HUX-004 (SHOULD; MUST for GUI palette)** human CLI/command discoverability built on R-CLI-005
  introspection: `--help` per verb, shell completion, in-GUI command palette.
- **R-HUX-005 (MUST)** human diagnostics presentation: in-editor Problems panel + inline markers
  (click-to-navigate) rendering the R-FILE-003 structured diagnostics.
- **R-HUX-006 (MUST for in-context instance/override editing; SHOULD rest)** viewport quality bar:
  multi-select, 3D grid + snapping, transform-space/pivot modes, alignment, and in-context
  scene-instance + override editing (the GUI face of L-35, so composition isn't CLI-only).
- **R-HUX-007 (MUST)** GUI asset browser: drag-drop import, thumbnail/preview (reuse R-HEAD-004
  offscreen render), drag-to-place into the viewport, inspector material assignment.
- **R-HUX-008 (SHOULD)** visual 3-way scene-merge/conflict presentation (pairs with R-FILE-012 MUST).
- **R-HUX-009 (design principle, SHOULD)** the zero-AI path is feature-complete relative to the AI
  path: a complete game is buildable with no AI usage through GUI/CLI. Decouples tooling quality
  from the ai-game.dev subscription (L-57's royalty waiver is a *pricing* lever, not a tooling gate).
- **R-HUX-010 (SHOULD)** in-editor contextual help (tooltips on inspector fields/gizmos, getting-
  started panel referencing R-QA-006 samples). Full tutorials/community: post-v1.
- **R-HUX-011 (SHOULD)** human-interaction latency budget (gesture→viewport, selection, inspector
  commit) as an M5 exit criterion, complementing the M1 AI-scale budgets.
- Ensure every authored kind's schema exposes a `notes` field and docs surface it as "how to comment"
  (L-32 bans JSON comments).
