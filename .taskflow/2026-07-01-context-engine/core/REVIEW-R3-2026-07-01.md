# Design Review — Round 3 (2026-07-01) — competitive strategy · build/toolchain reality · AI end-to-end

> Campaign round 3 (rounds 0–2 → PRs #110/#111/#112). **Verdict:** the technical design is now
> deeply hardened; round 3 exposed (a) the STRATEGY layer is absent (no beachhead, no moat
> statement, no acknowledged gaps — owner decisions), (b) the build/toolchain story is the
> least-honest layer (two internal MUST-contradictions), and (c) full agent autonomy breaks at

## Autonomous decisions (TD delegation) — encode this round

### Build & toolchain honesty [build reviewer #1–#12]
- **R-BUILD-007 (MUST, new)** — Apple-target constraint: iOS/macOS builds require a macOS build
  agent with Xcode (signing, SDKs are non-fetchable). The headless-CLI guarantee (R-BUILD-002) is
  PER-AGENT; "all six platforms" = orchestration over a build-agent pool incl. ≥1 macOS host.
  Amend R-BUILD-002 + M8 exit accordingly.
- **R-BUILD-005 split** — code signing + minimal packaging (APK/AAB signing; iOS provisioning +
  entitlements) → **MUST** (unsigned mobile "builds" aren't builds); store-submission/age-rating
  hooks stay COULD. M8 de-risk list names Android SDK/Gradle/JDK + Xcode signing.
- **L-42 / R-PKG-002 amend** — replace "a single pinned Clang toolchain" with a **per-target
  toolchain manifest** (compiler distribution + version + sysroot + ABI; engine-fetched-signed vs
  dev-preinstalled): mainline clang (Linux), clang-cl + MSVC STL/Win SDK (Windows, non-fetchable),
  Apple clang + Xcode (non-fetchable), Android NDK clang, Emscripten's forked LLVM (web). Note
  vcpkg community-triplet reality: the custom registry carries per-triplet port patches for
  non-desktop targets (ongoing maintenance) [#12].
- **R-VER-003 amend** — pin the **JS build toolchain** (Node.js + tsc + bundler) in the pin set;
  bundler output deterministic (stable module order, no timestamps); Node is a stated dev
  prerequisite (the embedded VM is not Node) [#4].
- **R-LANG-005 amend** — correct "AOT for web" (browsers compile WASM themselves); true native-AOT
  targets = iOS/console; the WASM→native AOT toolchain (wamrc / wasm2c+clang / Cranelift-compile)
  is an **M0/M3 spike deliverable with a size+throughput acceptance bar**; JS-VM bytecode
  precompile (hermesc/qjsc) budgeted in R-BUILD-006 [#5].
- **R-KERNEL-003 amend** — specify the DCE mechanism: build-time GENERATED registration TU (only
  referenced packages registered — static-initializer self-registration structurally defeats
  --gc-sections) + uniform LTO across from-source ports + linker GC; M1 de-risk item [#6].
- **R-BUILD-006 / L-28 amend** — LTO/DCE link steps are per-build-per-target and cache-EXEMPT
  (sccache-class caches cache per-TU compiles, not links); budget accordingly [#7].
- **R-PKG-004 / R-VER-003 scope-down** — reproducibility = "identical given the same
  machine/toolchain profile (content-addressed cache reuse)", NOT bit-identical cross-machine
  binaries (the docs already concede cross-machine import nondeterminism); if bit-identical is
  ever wanted it's a new requirement (SOURCE_DATE_EPOCH, -ffile-prefix-map, deterministic ar) [#8].
- **R-REND-005 amend + §7 risk row** — name the shader chain (glslang/DXC → SPIR-V → SPIRV-Cross;
  SPIR-V→WGSL via Tint/Naga = sole web path post-L-56, flagged maturity risk); shader compilation +
  variant generation are **derivation-graph nodes** (cached, keyed per R-FILE-010); WGSL tool
  choice = M0/M4 spike deliverable [#9].
- **§4/§7 amend** — name the native WebGPU backend (Dawn or wgpu-native) + risk row (Dawn is
  GN/depot_tools, not CMake-native — real port maintenance); the WEB RHI backend binds browser
  WebGPU (webgpu.h→JS), NOT a Dawn cross-compile — scope M4 "identical visuals" honestly; allow a
  narrow **signed-prebuilt exception** (verified per R-SEC-009) for build-hostile heavy libs [#10].
- **R-BUILD-008 (MUST, new)** — developer bootstrap: per-target enumeration of engine-fetched
  (signed, R-SEC-009) vs dev-preinstalled toolchains; **`context doctor`** validates presence/
  versions with R-CLI-008 machine-readable diagnostics; promote the fetch-and-verify mechanism
  (R-BUILD-004) to MUST for fetchable toolchains [#11].

### Agent autonomy closure [e2e reviewer F-1…F-10]
- **R-SEC-011 (MUST, new) — non-interactive scope provisioning + async consent** [F-1]: an
  operator-pre-authorized scoped token (explicit scope set incl. build+install) can be minted at
  daemon/agent launch (audited); consent gates return machine-readable
  `code=consent_required {scopeRequested, approvalRef, retriable-after-grant}` routable to an
  out-of-band async approver; a granted approval lets the same idempotency-keyed op RESUME.
- **Autonomy-envelope statement (amend R-SEC-001 + new doc para)** [F-2]: the fully-autonomous
  headless envelope = the sandboxed tier (TS + WASM); ANY native-tier action (native package,
  native importer, from-source C++ dep) is a human-approval boundary by design — agents degrade to
  request-approval-and-park (R-SEC-011), never fail opaquely.
- **R-LANG-010 amend** [F-3]: project/package-authored component types are **runtime-registered
  (data-driven archetype storage) with NO native rebuild in v1** — the hot autonomous loop covers
  component-type authoring; a native-codegen fast path may exist as an optimization, never as the
  only path. M3 pins this.
- **R-FILE-012 amend + new agent verb** [F-4]: `context merge-file --json` returns a
  machine-readable conflict envelope `conflicts:[{path, base, ours, theirs}]` — NEVER silent
  last-writer-wins, NEVER invalid-JSON markers; new `context resolve-conflict --path … --take
  ours|theirs|--value` verb; R-HUX-008's human UI renders the same structured output.
- **R-BUILD-009 (MUST, new) — headless build smoke-run** [F-5]: for headless-capable targets the
  build CLI launches the packed artifact, steps N ticks against the SHIPPED RuntimeKernel, asserts a
  boot/state signal, returns it in the R-CLI-008 envelope; non-headless targets declare so.
- **R-QA-005 amend** [F-6]: monotonic **`simTick`** counter queryable via RPC + returned in the
  step-result envelope — the stepping-specific replacement for idempotency keys (lost-ack =
  read counter, retry the delta).
- **R-CLI-008 amend** [F-7]: build-pipeline failures enumerated in the error catalog
  (`build.aot_failed`, `build.transcode_failed`, `build.template_unverified`,
  `build.toolchain_fetch_failed`, `build.link_failed`) with retriable + pointer.
- **R-QA-006 amend** [F-8]: `context new`'s DEFAULT template yields a minimal RUNNABLE skeleton
  (a scene + camera + startable session; non-error first query/step) — MUST for the default
  template; note describe=contract vs query=world-state in R-CLI-013/006.
- **R-CLI-006/008 amend** [F-9]: define `generationAfter` = the generation the write will be
  incorporated into (barrier-resolvable); `--after-hash H` (canonical) = the own-write barrier;
  `--after-generation` = for observed foreign generations.
- **L-52 amend** [F-10]: state plainly that visual correctness is NOT autonomously verifiable on a
  GPU-less host by design; autonomous visual QA requires an explicitly-provisioned GPU worker
  (R-HEAD-004) as an opt-in stage.

### Strategy-layer doc fixes (TD-encodable; owner rulings pending below) [competitive reviewer]
- **Durable-moat statement** (README + DESIGN-DECISIONS): the moat = file-authoritative +
  headless-complete + CLI-complete core (incumbents cannot retrofit without re-architecting);
  the MCP adapter is table stakes (we ship it for competitors ourselves). "An agent can build,
  run, verify, and ship a game with zero GPU and zero GUI" is the demo no incumbent can match [#1].
- **"Why a new engine and not MCP-on-Unity" rationale** (README): anchored on capabilities
  incumbent architectures forbid — true headless-complete, files-as-truth, GPU-free parallel
  agent authoring, native determinism [#10].
- **"Acknowledged competitive gaps at v1" section**: rendering fidelity out-of-box (M9 optional),
  asset-store maturity, console reach, middleware depth, learning content, engine maturity — each
  with the conscious reason it's acceptable [#6].
- **npm honesty (R-PKG-001 amend)**: npm = CODE reuse (pure-computation packages under the
  constrained ABI — no Node built-ins/native addons/threads); it does NOT solve the ASSET
  ecosystem; asset cold-start is an acknowledged risk requiring deliberate seeding (first-party
  starter packs, R-QA-006 samples as real playable templates). If npm-reuse is marketed, a
  compatibility corpus (N popular packages proven to run) becomes a requirement [#3].
- **R-LANG-002 rationale rewrite**: TS is chosen because it is the language LLMs write most
  reliably (largest corpus) — the gameplay language is part of the AI-first moat; audience = web
  devs + AI-builders, not incumbent migrants; no engine-to-engine importer in v1 (acknowledged
  gap; post-v1 growth lever TBD) [#5].
- **Free-tier framing (L-57 note)**: "free forever under $1M lifetime, full engine, no
  subscription required, zero AI required (R-HUX-009)" stated loudly; clarify the subscription
  buys AI usage, not the engine [#4 partial — license re-litigation is owner's, below].
- **L-59 (owner ruling, 2026-07-01) — no custom LSP**: data format stays canonical JSON + per-kind
  JSON Schema (L-32) — existing editor tooling (schema-driven autocomplete/validation/hover) is
  reused, not rebuilt; cross-file semantic intelligence lives in EditorKernel (the project-level
  language server, L-19) exposed via CLI/RPC/MCP — the AI path needs no text-editor LSP; an
  optional thin LSP shim forwarding to EditorKernel's query API is post-v1 sugar. Terminology note:
  "EditorKernel as project language server" ≠ "text-editor LSP".

## Owner rulings (asked & RULED 2026-07-01)
1. Target beachhead — **RULED: ADOPT the proposed wedge** (headless AI-training/RL + deterministic
   server-authoritative sim/multiplayer + AI-generated 2D/simple-3D, on desktop/Linux-server/web);
   "general 3D engine" is the destination, not the day-one claim. → encode in README + plan (R3b).
2. v1 scope — **RULED: DEFER M9 advanced graphics + XR world-space UI to explicit v2**; v1 =
   M1–M8 (desktop + Linux-headless + web + Android, 2D + baseline-3D PBR); iOS stays in v1 but is
   allowed to trail. → re-sequence the plan (R3b).
3. License — **RULED: KEEP the proprietary source-available EULA + market the free tier loudly**
   ("free forever under $1M, full engine, no subscription, no AI required"); the grassroots/MIT
   tradeoff is recorded as an acknowledged, conscious decision. → encode (R3b).
4. Naming — **OPEN, under discussion**: owner leans "Context Game Engine" as the qualified brand
   but wants to discuss; **urgency RAISED by ruling 5** — the name ships at first public push, so
   it must be settled before the repo goes public (or bootstrap private, flip public when named);
   route a naming brief to marketing before any public artifact.
5. **Public release from the start of development (owner ruling, 2026-07-01)** — L-57 amendment
   for R3b: the engine repo is PUBLIC from day one under a custom **Context Engine EULA**
   (Unreal-mechanism replica, un-gated): full source visible; grant = develop/build/ship projects
   made with the engine; FORBIDDEN = redistributing the engine (source or binaries except embedded
   in a shipped game), creating/distributing a derived or competing engine/tool/middleware, any
   commercial exploitation of the engine itself; royalty terms (2% > $1M, per-version-locked) in
   the same license; protection = copyright + games-only grant + trademark (not an access gate).
   **CLA correction: full copyright ownership requires a proper CLA with copyright assignment (or
   exclusive unrestricted grant) before any external contribution merges — DCO alone is
   INSUFFICIENT and is struck from L-57's "CLA/DCO" wording.** Enforcement stays contractual/
   legal-only (round-2 ruling; no phone-home). EULA drafting moves EARLIER: a working LICENSE
   (counsel-reviewed) must exist before the first public push — legal-compliance-officer task.
6. **Royalty terms UPDATED (owner ruling, 2026-07-01)** — supersedes the 2% > $1M-lifetime terms:
   **2% royalty on gross revenue per product ABOVE $200,000 per YEAR** (annual threshold, resets
   each year; TD-recorded as marginal — the 2% applies to the revenue above the threshold, not a
   cliff on all revenue — owner may correct). Waiver unchanged: games developed under an active
   ai-game.dev subscription pay no royalty. Terms stay locked per engine version, never
   retroactive; enforcement contractual-only. Free-tier framing becomes: "free under $200k/year,
   full engine, no subscription, no AI required." Precise definitions (gross revenue, per-product,
   measurement year) land in the EULA draft. → R3b replaces every "$1M lifetime" reference
   (L-57, README, tracker framing) with the annual terms.
