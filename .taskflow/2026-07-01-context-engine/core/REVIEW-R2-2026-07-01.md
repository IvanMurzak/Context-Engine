# Design Review — Round 2 (2026-07-01) — security coherence · API/contract design · consistency

> Campaign round 2 (round 0 = 4-lens → PR #110; round 1 = perf/concurrency/DX → PR #111).
> Three lenses on the post-R1 docs. TD-verified. **Verdict:** architecture sound; the R1 fixes
> applied cleanly (consistency pass confirms ID integrity + amendment coherence). Two real
> structural gaps remain — (A) the security trust boundary is implicitly the OS user while the
> whole threat model runs *as* that user, with no cryptographic trust root; (B) the public API
> shape layer (verb grammar, error model, self-description, versioning) is under-specified and
> M1 is about to freeze the RPC/event schema. Fix both this round.

## A. Security — new trust-root + honest isolation (anchor of the round)

**Root cause (F-META + F1/F2/F6/F9):** "signed / trusted / attested / verified" appear across
R-SEC-001, R-SIM-005/L-54, R-BUILD-006, R-FILE-010, R-SEC-005 but NONE is defined — all are
forgeable self-declared flags or unauthenticated fetches; and per-user ACL / per-user cache /
single-token "isolation" does not defend against same-user untrusted code (agents, npm/vcpkg
packages, assets, editor extensions all run as the user).

- **R-SEC-009 (MUST) — Cryptographic trust root & artifact signing** *(new; anchors the rest)*:
  pinned root of trust (Sigstore/TUF-style metadata), per-artifact detached signatures, mandatory
  verify-before-use for engine binaries, the pinned toolchain, export templates, native packages,
  and any cross-trust-domain cache entry; fail closed on verification failure. Every "signed/
  trusted/attested/verified" clause elsewhere MUST cite R-SEC-009.
- **R-SEC-001 + L-49 amend (F1) — honest TS isolation**: in v1 ALL TS is ONE trust domain (single
  shared VM per R-LANG-011 → no package-vs-package isolation); stop calling it "sandboxed per
  package." Enumerate the TS host ABI: no ambient `fs`/`net`/`process`/native-addon; only
  engine-injected, capability-gated bindings. Per-package isolates = post-v1. WASM tier remains the
  genuinely-sandboxed tier.
- **R-FILE-010 amend (F2) — cache poisoning**: code/executable artifacts (WASM, compiled C++,
  shaders) are trusted from the shared cache ONLY if signed by the trust root (R-SEC-009) or
  produced by this trust domain; otherwise partition per-domain or verify-by-re-derivation on first
  cross-domain read; the R-BUILD-006 remote warm cache MUST be signed+verified, not merely "trusted."
- **R-EDIT-001 amend (F3) — CEF extension sandbox** (distinct from L-49): Node/native integration
  OFF, per-extension isolated renderer + site isolation, strict CSP, `sandbox`-attributed iframes
  for untrusted panels, no direct daemon socket/token access from extension contexts, capability-
  scoped bridge (default read/query, never ambient file-write/build/install).
- **R-VER-004 / R-BUILD-004 / R-OBS-006 amend (F4)** — engine-version, toolchain, export-template,
  and update-channel fetches MUST be signed + verified (R-SEC-009) + TLS/cert-pinned, verify-before-
  execute, fail closed. (Backdoored toolchain = worst case.)
- **R-SEC-002 amend (F5)** — capability enforcement: MUST for the WASM tier (import-gating); TS =
  tier-level capability gating at the injected-binding layer (not per-package in v1, per F1); native
  = consent-gate + advisory, stated plainly. Reword R-SEC-001 so it doesn't promise per-package
  sandboxing the layer can't deliver.
- **R-SEC-007 amend (F6) → MUST** — scope enforcement in the RPC **dispatcher**, not the MCP adapter
  (adapter filtering is bypassable via direct RPC); define scoped-token minting + elevation behind a
  consent gate; stop relying on the single ambient 0600 token for local authorization.
- **R-SEC-007 / R-FILE amend (F7)** — a file-write scope is effectively code-execution: derivation-
  triggered dependency installs REQUIRE build+install scope (writing a new dep without it = a
  diagnostic, not an auto-install); native-importer invocation is gated by the native trust gate
  independent of who wrote the asset.
- **R-SIM-005 / L-54 amend (F8)** — the engine's deterministic toolchain PRODUCES the
  `deterministic:true` attestation from verified build flags (not a trusted manifest bit);
  third-party WASM attestations are reproduced/verified by the determinism harness before acceptance.
- **R-SEC-003 amend / new R-SEC-010 (F9) — least-privilege & exfiltration**: daemon runs
  least-privilege; importer/build/VM child processes get a scrubbed environment; TS/WASM tiers get
  no ambient network by default; optional pre-write/pre-commit secret scanning surfaced as a
  diagnostic.
- **L-57 amend (F10) — royalty enforcement is CONTRACTUAL-ONLY** *(TD decision, protects privacy +
  source-available promise; does not change money terms)*: NO license-server call, NO subscription
  check, NO revenue telemetry in EditorKernel, RuntimeKernel, or shipped game builds. Any future
  verification must go through the O-6 privacy-gated path and never ship in the game runtime.
- **O-7 / L-57 amend (F11) — license allowlist**: deny-by-default (unknown/missing license = CI
  fail), scans npm + vcpkg transitive graphs, fails on any copyleft linked into shipped engine
  cores, permits permissive build-only tools, emits an SBOM.
- **R-SEC-008 amend (F12)** — path-jail enforcement is TOCTOU-safe (openat/O_NOFOLLOW /
  resolve-then-verify-by-fd / re-realpath-after-open, not validate-then-open); applied on the
  importer-subprocess and intent-log-resume paths too.
- **R-FILE-004 amend (F13)** — intent-log entries are integrity-checked (HMAC with a per-incarnation
  key; trust only entries this daemon wrote); every resumed write passes the same jail (F12) + CAS
  as a fresh write, never blind-replayed.
- **R-SEC-005 / L-42 amend (F14)** — vcpkg from-source builds run each lib's build scripts = build-
  time code execution; run under the native consent gate + an isolated least-privilege build env
  (scrubbed env, fetch-only network, no cache write outside its own key); SHA-pinned source
  artifacts in the engine registry.
- **L-49 amend (F15)** — soften the crash-containment claim to match R-SEC-004 (COULD): the
  in-process TS tier is NOT crash-isolated in v1; WASM/subprocess tiers are the containment story.
- **R-LANG-009 amend (F16)** — cheap+reliable ArrayBuffer detach is a HARD GATING criterion for the
  §2d VM choice (not merely scoring); if no candidate can detach, the fallback is copy-in/copy-out
  views (forfeiting zero-copy) — never ship retained-view use-after-free.
- **R-SEC-006 amend (F17)** — specify the per-OS importer-subprocess sandbox primitive (seccomp-bpf
  / Windows AppContainer or Job Object / dropped privileges); third-party importers declare + run
  under the same isolation or trip the native consent gate.
- **R-BRIDGE-007 amend (F18)** — authenticate the server to the client (not just client→server);
  integrity-protect `instance.json`; require mutual auth before any remote-exposure mode.

## B. Public contract layer — author before M1 freezes the schema (new R-CLI-007…017)

- **R-CLI-007 (MUST) — verb grammar & namespace**: one shape `context [<ns>:]<noun> <verb> [--flags]`
  + a fixed core-flag set (`--json`, `--project`, `--if-match`, `--after-generation`, `--dry-run`,
  `--idempotency-key`); engine verbs = bare namespace; package verbs MUST carry the package's
  reserved namespace, collision-checked at add-time; the grammar is part of the versioned contract.
- **R-CLI-008 (MUST) — uniform result envelope + error catalog**: every CLI/RPC result is
  `{ ok, data|error, generationAfter, warnings[] }`; `error = { code, message, retriable, pointer?,
  data? }` with `code` from a stable, versioned, introspectable error-code catalog; a fixed exit-code
  table; the JSON-RPC error `data` carries the same code. Folds ALL "machine-readable diagnostic"
  producers (R-FILE-003, R-BRIDGE-006, R-SEC-008, R-PKG-005) into this one schema (F13-consistency).
- **R-CLI-009 (MUST) — single registry / structural parity**: one registry is the source of truth
  for the whole surface (file-rewriter verbs, RPC methods, MCP tools, command palette all generated
  from it); hand-maintained parity prohibited; CI proves CLI≡RPC≡MCP≡introspection.
- **R-CLI-010 (MUST) — capability negotiation + deprecation lifecycle**: replace R-BRIDGE-006's
  version-EQUALITY with a handshake `{protocolMajor, supportedCapabilities[], minClientProtocol}`;
  succeed within a compat window, degrade to the negotiated subset, hard-fail only outside it;
  written deprecation policy (deprecated→removed over ≥N minors, `deprecated:true`+`removedIn` in
  introspection, stable method-ids). (Amends R-BRIDGE-006 + R-CLI-004.)
- **R-CLI-011 (MUST) — batch result contract**: a batch / `query|set` returns
  `{ perTarget:[{path, ok, hashAfter, error?}], generationAfter, applied, failed }`; `--atomic-plan`
  = CAS every target against planning-time hashes, refuse the whole batch on any mismatch (plan-level
  all-or-nothing WITHOUT runtime transactions — L-25 stands); one `settled` barrier for the batch.
- **R-CLI-012 (MUST) — query language spec**: one grammar (EBNF in the versioned contract), an
  enumerated operator set (equality/range/boolean/existence/string), MANDATORY total result ordering
  (stable key, default entity-id), a cursor-pagination contract unified with R-BRIDGE-008, defined
  NFC+case string semantics; the SAME predicate/projection language across derived-world, live-sim,
  and schema introspection.
- **R-CLI-013 (MUST) — whole-contract self-description**: one artifact/endpoint
  (`context describe --json`, mirrored over RPC) emits the complete versioned machine description —
  every verb+params+flags, every RPC method+schema, every event topic+payload schema, every file
  kind + component-type schema, the full error-code catalog, protocol/capability version. **Fix
  R-CLI-005** so its text actually covers verbs/params (reconciles the R-HUX-004 claim that it does).
- **R-CLI-014 (SHOULD) — event/topic introspection**: topics and event-type payload schemas are
  runtime-discoverable (extends R-CLI-005/013); packages may register namespaced topics + event
  schemas.
- **R-CLI-015 (MUST) — subscription protocol**: concrete methods `subscribe{topics, pathScope,
  sinceSeq?}→{snapshot, subId}`, `unsubscribe{subId}`, `ack{subId, seq}`; ring-buffer retention
  defined relative to the slowest acked cursor; pin in R-CLI-004 (don't defer the whole thing to M1).
- **R-CLI-016 (MUST) — idempotency**: mutating/side-effecting RPC/CLI ops accept a client-supplied
  `--idempotency-key`; the daemon records `(key→{resultEnvelope, generationAfter})` for a bounded
  window and REPLAYS the stored result on retry (covers the dropped-ack case; note stepping per
  R-QA-005 is otherwise non-idempotent).
- **R-CLI-017 (MUST) — transport-portable large results**: the oversized-response handle is an
  opaque resource URI fetched over the same channel (`resource.read{handle, range}` / `context fetch`);
  the local temp-file path is an optimization only when client+daemon share a filesystem; reconcile
  handle-vs-cursor as one large-result contract. (Amends R-BRIDGE-007.)
- **R-CLI-012 read-your-writes hash disambiguation (F12-api)**: mutations return BOTH hashes
  (labelled); `--if-match` uses the raw-byte hash; the read-your-writes barrier resolves on the
  canonical-content hash or (preferably) on `--after-generation` (unambiguous). (Amends R-FILE-001
  cross-ref + R-CLI-006.)
